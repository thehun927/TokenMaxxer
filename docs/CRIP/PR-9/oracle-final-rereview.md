## B1 — overlapping last-only publication: closed

The original blocker was that OpenCode v1.18.15 invokes plugin event callbacks fire-and-forget, so two same-project `session.compacted` handlers can overlap and an older async history read could previously overwrite a newer last-only diagnostic.

The remediation now:

- captures a monotonic receipt sequence before async history/diagnostic work;
- captures the observation timestamp at receipt;
- keeps history retrieval outside publication serialization;
- serializes only the short publication step per project + artifact;
- uses the module-global sequence across plugin instances in the same process;
- refuses an older sequence after a newer sequence has published;
- consults existing persisted mtime/timestamp on the first observation in a process as best-effort cross-process protection;
- keeps publication failures non-fatal and independent of STATE/revision/IdleWriteOutcome/`.commit-pulse`.

The new deferred-promise regressions exercise the actual race shape: older starts first, newer finishes first, older finishes last. They cover both result and prompt artifacts and verify the newer observation remains persisted.

The initial Oracle listed full two-process publication ordering as **preferable**, not a release requirement. The implementation provides best-effort disk protection across processes but the authoritative monotonic queue is same-process. That is acceptable for this PR-9 gate and does not weaken any PR 1–8 invariant.

## B2 — prompt hard bound/header injection: closed

Every text header value now passes through bounded single-line normalization before header construction:

- session ID is bounded;
- raw requested mode has a small explicit cap;
- effective mode is normalized from the trusted effective value;
- fallback reason is bounded;
- CR/LF/tab/other control characters are visibly escaped rather than becoming structural lines.

The payload budget is calculated after normalized metadata, and the full rebuilt artifact remains constrained to `COMPACTION_PROMPT_ARTIFACT_MAX_BYTES` (96 KiB UTF-8). Hostile huge/multiline/multibyte metadata therefore cannot create an oversized header or inject fake prompt-header fields/payload delimiters.

## B3 — result read-side validation: closed

`validateCompactionResultDiagnostic()` is now authoritative for persisted data rather than trusting normal builder output. It rejects:

- raw JSON over 4096 UTF-8 bytes;
- session IDs over 256 characters;
- unavailable reasons over 500 characters;
- negative, fractional, unsafe or non-finite summary byte counts;
- malformed/impossible completion timestamps;
- SHA-256 values that are not exactly 64 lowercase hex characters.

The builder was also aligned so generated byte counts remain non-negative safe integers. Corrupt/external artifacts return `ok:false`, allowing status to continue treating them as unavailable/invalid diagnostics instead of rendering them as durable truth.

## B4 — arbitrary outer error bounds: closed

The outer compaction-hook and event-handler catches now use safe bounded error conversion. A hostile value cannot emit unbounded host/filesystem text through `client.app.log`, and a hostile `toString()` cannot escape the error-handling path.

Focused regressions cover multi-kilobyte hook/event errors while the logging transport itself throws; both primary handlers remain non-throwing and logged values stay bounded.

## Previously-cleared PR-9 behavior still holds

The rereview found no regression in the already-cleared architecture:

- no process-global last-compaction status authority;
- prompt snapshots and successful result metadata remain distinct artifacts;
- `session.compacted` remains the successful completion authority;
- full summaries/conversations are not persisted for diagnostics;
- local-first/global-fallback diagnostic storage remains intact;
- status remains durable per-project and reload-safe;
- terminal audit/model-health persistence remains best effort;
- audit guard creation remains required/fail-closed;
- file activity distinguishes read/edit/write/search/shell reference categories;
- PR-7 compaction semantics and PR-8 budgets remain intact;
- TMTUI `.commit-pulse` still means successful STATE commit only.
