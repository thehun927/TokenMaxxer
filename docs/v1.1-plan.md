# tokenmaxxer v1.1 — Implementation Plan

> LLM-based extraction via `small_model` + session history array for true multi-session windowing.

---

## 0. Context

### What v1 has
- **Heuristic extraction** (`extractFactsHeuristic`): regex-based, conservative, produces `decisions: []` on most real sessions. Misses decisions stated in unusual phrasing. Can't distinguish "discussing decisions" from "making decisions."
- **`last_used_in_session`**: tracks only the current session. The bounded durable block (M5) includes decisions referenced in the current session as "recent." True "last 3 sessions" windowing is not possible.

### What v1.1 adds
1. **LLM-based extraction** — send a canonical input containing a capped prior STATE.json snapshot, a compressed source transcript, and file candidates to `small_model`; request validated structured output through `format: { type: "json_schema", schema }`, then fall back to the v1 heuristic on failure.
2. **Session history array** — `recent_sessions: string[]` in MemoryFile, capped at 10. The bounded durable block uses "last 3 sessions" from this array instead of just the current session.

### Product decisions (resolved)

| Decision | v1.1 behavior |
|---|---|
| Extraction session | **Visible and retained.** Cache misses create a normal session titled `tokenmaxxer extract · <project> · <source session>` with tokenmaxxer metadata. Do not delete it. |
| Result cache | Persist in STATE.json. Cache key is source session ID + SHA-256 canonical-input fingerprint + `provider/model`. A cache hit makes no new LLM call or extraction session. |
| Prior memory | Include a capped STATE.json snapshot in the extraction prompt as prior, potentially stale context. Ask the model for the current-session delta, not a copy of old memory. |
| Output protocol | Put `model` and top-level `format: { type: "json_schema", schema }` on every `session.prompt`; consume and Zod-validate `result.data.info.structured`, never assistant text. |

### API constraints (verified from opencode source)
- **No one-shot LLM API** — create a normal extraction session, prompt it, and retain it as visible audit history; never call `session.delete`
- **Per-prompt model override**: `body.model = { providerID: string, modelID: string }`
- **Small model**: during `session.idle` only, read `config.small_model` via `client.config.get()`, parse `"provider/model"`, and pass it as `body.model`; plugin initialization must not call `config.get`
- **Fire-and-forget is safe**: plugin runs in-process, `session.prompt` has `timeout = false`
- **Structured output**: `format` injects a required, schema-validated `StructuredOutput` tool; consume `result.data.info.structured`
- **No provider-native JSON mode**: `format` is tool-based and works with a per-prompt small-model override
- **Retry caveat**: `retryCount` is not server-enforced; tokenmaxxer makes exactly one explicit retry after an error or invalid structured result, then preserves the heuristic facts
- **Session visibility**: do not delete extraction sessions; they are retained as audit history

## 1. Feature 1: LLM-based extraction

### 1.1 Architecture

```
session.idle event
  → writeMemoryOnIdle
    → persist heuristic facts immediately (v1 fallback / process-exit safety)
    → build canonical LLM input:
        capped prior STATE.json + compressed source transcript + file candidates
    → SHA-256 canonical-input fingerprint
    → cache hit for { source session ID, fingerprint, provider/model }?
      → yes: use cached validated facts; create no session and make no prompt call
      → no + LLM enabled:
          → create visible extraction session (retain it; never delete it)
          → session.prompt with body.model + top-level format(json_schema, schema)
          → read and Zod-validate result.data.info.structured
          → one explicit retry for an error or invalid structured result
          → re-read memory, merge LLM delta, persist cache
          → failure: retain already-persisted heuristic facts
    → record source session in recent_sessions (cap 10)
    → pruneOld → writeMemory
```

### 1.2 New files

```
src/memory/
  extract-schema.ts  # Zod facts schema + JSON schema for format
  extract-llm.ts     # LLM-based extraction
  extract-prompt.ts  # Canonical input, fingerprint, extraction prompt builder
```

### 1.3 `extract-llm.ts` — implementation spec

> **Final v1.1 contract — this is the implementation contract.**
>
> - Create a **visible, retained** extraction session. It is a normal audit session; never call `session.delete`.
> - Build one canonical input from a capped prior STATE.json snapshot, compressed source transcript, and tool-derived file candidates. Cache by source session ID + SHA-256 canonical-input fingerprint + provider/model.
> - Send `body.model` and top-level `body.format = { type: "json_schema", schema }` together.
> - Read and Zod-validate `result.data.info.structured`; never inspect assistant text or parse free-form JSON.
> - If the prompt errors or the structured value is invalid, issue exactly one explicit retry in the same retained extraction session. If that retry fails, keep the already-persisted heuristic facts.

The implementation creates the extraction session once, then uses one two-attempt loop for both prompt errors and invalid structured values. It must not retry more than once and must not create a replacement extraction session. In all cases the session created for extraction remains visible and retained.

`getLLMConfig(client)` is called only from the `session.idle` path, after the plugin has initialized. Plugin initialization returns its hooks without calling `client.config.get()`.

```ts
interface LLMExtractionConfig {
  enabled: boolean
  model?: { providerID: string; modelID: string }  // parsed from config.small_model
}

/** Parse "provider/model" format from config.small_model. */
export function parseSmallModel(smallModel: string | undefined): { providerID: string; modelID: string } | undefined {
  if (!smallModel) return undefined
  const separator = smallModel.indexOf("/")
  if (separator <= 0 || separator === smallModel.length - 1) return undefined
  return {
    providerID: smallModel.slice(0, separator),
    modelID: smallModel.slice(separator + 1),
  }
}

/** Called by writeMemoryOnIdle, never by plugin initialization. */
export async function getLLMConfig(client: unknown): Promise<LLMExtractionConfig> {
  if (process.env.TOKENMAXXER_LLM_EXTRACT !== "1") return { enabled: false }
  try {
    const c = client as { config?: { get?: () => Promise<{ data?: { small_model?: string } }> } }
    const config = await c.config?.get?.()
    const model = parseSmallModel(config?.data?.small_model)
    return model ? { enabled: true, model } : { enabled: false }
  } catch {
    return { enabled: false }
  }
}

/** Main extraction function; config has already been resolved inside session.idle. */
export async function extractFactsLLM(
  canonicalInput: CanonicalExtractionInput,
  sourceSessionID: string,
  projectName: string,
  client: unknown,
  config: LLMExtractionConfig,
): Promise<ExtractedFacts | null> {
  if (!config.enabled || !config.model) return null

  const cacheKey = makeExtractionCacheKey(sourceSessionID, canonicalInput.sha256, config.model)
  const cached = await readExtractionCache(cacheKey)
  if (cached) return cached.facts

  // Create a normal, visible session and retain it as an audit trail.
  const extraction = await client.session.create({
    body: {
      title: `tokenmaxxer extract · ${projectName} · ${sourceSessionID.slice(-8)}`,
      metadata: { tokenmaxxer: { kind: "llm-extraction", sourceSessionID } },
    },
  })

  const body = {
    model: config.model,
    format: { type: "json_schema" as const, schema: ExtractedFactsJsonSchema },
    parts: [{ type: "text" as const, text: buildExtractionPrompt(canonicalInput) }],
  }

  for (let attempt = 0; attempt < 2; attempt++) {
    try {
      const result = await client.session.prompt({
        path: { id: extraction.data.id },
        body,
      })
      const parsed = ExtractedFactsSchema.safeParse(result.data.info.structured)
      if (parsed.success) {
        await writeExtractionCache({ cacheKey, sourceSessionID, canonicalInput, model: config.model, facts: parsed.data })
        return parsed.data
      }
      // Invalid structured output: the second loop iteration is the one retry.
    } catch {
      // StructuredOutputError or another prompt failure: the second loop iteration is the one retry.
    }
  }

  // Heuristic facts were persisted before this function was called; return null so they survive.
  return null
}
```

### 1.4 `extract-prompt.ts` — extraction prompt builder

The prompt must:
- Fit within the small model's context window (haiku/flash: 200K tokens, but keep it small for cost)
- Explain the extraction fields and delta semantics; the `format` schema, not prompt text, defines the output shape
- Handle the source transcript efficiently (don't send 50 full messages)
- Include all three canonical-input components: capped prior STATE.json, compressed transcript, and file candidates

**Transcript compression strategy:**
- Extract only text parts (skip tool calls, step-finish, etc.)
- Cap each message to 500 chars
- Cap total transcript to 20 messages (last 20)
- This gives ~10K chars (~3K tokens) — well within small model limits

**Canonical input and cache identity:**

```ts
interface CanonicalExtractionInput {
  priorStateJson: string       // capped prior STATE.json memory snapshot
  compressedTranscript: string // last 20 text messages, 500 chars each
  fileCandidates: string[]     // tool-derived, normalized, capped and sorted
  sha256: string                // SHA-256 of canonical serialization below
}

export function buildCanonicalInput(
  messages: TranscriptMessage[],
  priorState: MemoryFile | null,
): CanonicalExtractionInput {
  // Cache metadata is excluded from the prior snapshot: writing a cache entry
  // must not change the fingerprint of the same source session and input.
  const priorStateJson = cap(JSON.stringify(priorState ? withoutExtractionCache(priorState) : {}), 8_000)
  const compressedTranscript = compressTranscript(messages)
  const fileCandidates = extractFileCandidates(messages).slice(0, 20).sort()
  const canonical = stableJson({
    prior_state: priorStateJson,
    source_transcript: compressedTranscript,
    file_candidates: fileCandidates,
  })

  return {
    priorStateJson,
    compressedTranscript,
    fileCandidates,
    sha256: sha256Hex(canonical),
  }
}

export function makeExtractionCacheKey(
  sourceSessionID: string,
  canonicalInputSha256: string,
  model: { providerID: string; modelID: string },
): string {
  return `${sourceSessionID}:${canonicalInputSha256}:${model.providerID}/${model.modelID}`
}
```

The cache key is the source session ID + SHA-256 canonical-input fingerprint + provider/model. A cache lookup happens before creating an extraction session. A hit makes no LLM call or session; merging the already-validated cached facts is idempotent.

```ts
export function buildExtractionPrompt(input: CanonicalExtractionInput): string {
  return `You are a fact extractor for a coding session. Use the current-session evidence below to produce the values required by the StructuredOutput schema supplied with this request.

The prior STATE.json snapshot is potentially stale context. Return only current-session facts or deltas; do not copy old facts merely because they appear in prior state. Use file candidates as corroborating candidates, not as proof that a file was changed.

Rules:
- current_task: describe what the current session is working on; use null when unclear.
- active_files: only files read, edited, or written in this source session; max 5, relative paths.
- decisions: only explicit decisions (for example, "let's use X" or "decided to go with Y"). Do not include discussions, descriptions, or hypothetical decisions.
- blockers: only blockers supported by the current session; otherwise use an empty array.
- next_steps: only next steps stated by the current session; max 5.
- Do not include code snippets, tool outputs, or file contents.
- Do not answer with assistant text or free-form JSON. Return the result through the required StructuredOutput tool.

CAPPED PRIOR STATE.json (potentially stale):
${input.priorStateJson}

COMPRESSED SOURCE TRANSCRIPT:
${input.compressedTranscript}

FILE CANDIDATES:
${input.fileCandidates.join("\n") || "(none)"}`
}
```

### 1.5 Structured result validation

```ts
export function validateStructuredResult(result: unknown): ExtractedFacts | null {
  const parsed = ExtractedFactsSchema.safeParse(result)
  return parsed.success ? parsed.data : null
}
```

Call it only with `result.data.info.structured`. There is no assistant-text fallback, code-fence stripping, `JSON.parse`, or other free-form response parser. An invalid value triggers the single explicit retry in `extractFactsLLM`; after that, the persisted heuristic facts remain authoritative for the idle write.

### 1.6 Dispatcher in `writer.ts`

Keep the heuristic extraction as the first durable write in `writeMemoryOnIdle`. Resolve config only after the `session.idle` event has entered the writer; never resolve it while the plugin is initializing.

```ts
async function writeMemoryOnIdle(opts: IdleOptions): Promise<void> {
  const messages = await loadSourceTranscript(opts.client, opts.sessionId)
  const priorState = await readMemory(opts)
  const heuristicFacts = extractFactsHeuristic(messages)

  // Persist the fallback before any detached LLM work.
  await mergeAndWriteMemory(opts, heuristicFacts)

  // This is the only session.idle path that may call client.config.get().
  const llmConfig = await getLLMConfig(opts.client)
  const canonicalInput = buildCanonicalInput(messages, priorState)
  const llmFacts = await extractFacts(
    canonicalInput,
    opts.sessionId,
    opts.projectName,
    opts.client,
    llmConfig,
  )

  if (llmFacts) {
    // Re-read after the async call so concurrent writes are not overwritten.
    await mergeAndWriteMemory(opts, llmFacts)
  }
  await recordRecentSession(opts, 10)
}
```

The LLM dispatcher receives the config already resolved by `session.idle`; it does not call `client.config.get()` itself. It also receives the canonical input, so the cache lookup occurs before creating a visible extraction session.

```ts
async function extractFacts(
  canonicalInput: CanonicalExtractionInput,
  sourceSessionID: string,
  projectName: string,
  client: unknown,
  llmConfig: LLMExtractionConfig,
): Promise<ExtractedFacts | null> {
  if (!llmConfig.enabled || !llmConfig.model) return null

  const llmFacts = await extractFactsLLM(
    canonicalInput,
    sourceSessionID,
    projectName,
    client,
    llmConfig,
  )
  if (llmFacts) {
    await log(client, "info", "LLM extraction succeeded", {
      decisions: llmFacts.decisions.length,
      active_files: llmFacts.active_files.length,
    })
    return llmFacts
  }
  // The heuristic facts were already written before the LLM attempt.
  await log(client, "warn", "LLM extraction failed, preserving heuristic facts")
  return null
}
```

### 1.7 Config

**Environment variable**: `TOKENMAXXER_LLM_EXTRACT=1` — enables LLM extraction (requires `small_model` in opencode config).

**No env var or no `small_model`**: heuristic extraction (v1 behavior, no change).

This makes v1.1 opt-in. Users who want better extraction set `small_model` in their config and `TOKENMAXXER_LLM_EXTRACT=1` in their environment. Everyone else gets v1 behavior. The `small_model` lookup is performed only after `session.idle` enters `writeMemoryOnIdle`; plugin initialization must not call `client.config.get()`.

### 1.8 Cost estimate

- Transcript: ~20 messages × 500 chars = ~10K chars ≈ 3K tokens
- Prompt overhead: ~500 tokens
- Response: ~500 tokens (schema-constrained result with 5-10 decisions)
- Total: ~4K input + 500 output per attempt; an uncached failure may use two attempts
- Claude 3.5 Haiku: $0.25/M input, $1.25/M output → ~$0.001 per extraction
- Gemini Flash: similar
- **Cost: ~$0.001 per uncached attempt, at most ~$0.002 for an idle event that needs the explicit retry** — negligible

### 2.3 Write logic

In `writeMemoryOnIdle`, record the source session after the heuristic/LLM merge:

```ts
// Track session history
const sessionId = opts.sessionId
if (!merged.recent_sessions.includes(sessionId)) {
  merged.recent_sessions.push(sessionId)
  // Cap at 10
  if (merged.recent_sessions.length > 10) {
    merged.recent_sessions = merged.recent_sessions.slice(-10)
  }
}
```

On a successful LLM extraction, upsert its validated facts and identity fields into `llm_extraction_cache` by `cache_key`, retaining at most 10 entries. On an LLM error or invalid result after the one retry, do not write a cache entry; the heuristic facts already persisted for this idle event remain in STATE.json.

### 2.4 Bounded durable block update

In `durable.ts`, update `isRecentSession`:

```ts
function isRecentSession(d: Decision, recentSessions: string[]): boolean {
  if (!d.last_used_in_session) return false
  // Durable recency is exactly the last three recorded source sessions.
  const lastThree = recentSessions.slice(-3)
  return lastThree.includes(d.last_used_in_session)
}
```

Update the call site in `buildDurableBlock`:

```ts
const recent = valid.filter(d => !d.foundational && isRecentSession(d, mem.recent_sessions))
```

## 4. Risks

| Risk | Mitigation |
|---|---|
| Small model not configured | `getLLMConfig` returns `{ enabled: false }` → heuristic fallback |
| LLM call fails (network, model error) | `extractFactsLLM` returns `null` → heuristic fallback |
| Model does not produce structured output | Detect `StructuredOutputError`, make one explicit retry, then retain heuristic result |
| Structured result has wrong shape | `ExtractedFactsSchema.safeParse(result.data.info.structured)` fails → one explicit retry, then heuristic fallback |
| Extraction sessions create list noise | Intentional product decision: retained, visible audit sessions with title + metadata; add retention controls only if real users request them |
| LLM extraction too slow (10+ seconds) | Fire-and-forget on session.idle — user doesn't wait. Log timing for monitoring. |
| LLM extraction produces false positives | The prompt explicitly says "only EXPLICIT decisions" and "do NOT include discussions about decisions." The LLM is better at this than regex. |
| Schema migration breaks existing STATE.json | Migration is additive (`recent_sessions: []`, optional `llm_extraction_cache`), tested with v1 data |
| `recent_sessions` grows unbounded | Capped at 10, oldest dropped |
| `config.small_model` format changes | `parseSmallModel` handles `"provider/model"` format; returns `undefined` on parse failure |
| Config lookup deadlocks startup | Never call `client.config.get()` during plugin initialization; resolve it only from `session.idle` |

## 5. Rollout strategy

1. **v1.1.0**: Ship with `TOKENMAXXER_LLM_EXTRACT=1` opt-in. Users who want better extraction set the env var + `small_model` in config. Everyone else gets v1 heuristic (no change).
2. **v1.2.0**: Make LLM extraction the default if `small_model` is configured. Heuristic becomes the fallback.
3. **v2.0.0**: Remove heuristic extraction entirely. LLM is the only path. `small_model` becomes a hard requirement.

## 6. Resolved architecture decisions

1. **Extraction sessions remain visible.** They are retained audit sessions, titled and tagged with the source session; no `session.delete` call is permitted.
2. **Canonical input is complete and stable.** It contains capped prior STATE.json, compressed source transcript, and file candidates. The cache key is source session ID + SHA-256 canonical-input fingerprint + provider/model.
3. **Config is read after startup.** `client.config.get()` runs only in the `session.idle` writer path, never during plugin initialization.
4. **Use top-level structured output.** Every prompt body includes `model` and `format: { type: "json_schema", schema }`. Consume and Zod-validate `result.data.info.structured`; no assistant-text or free-form JSON parsing.
5. **Retry is explicit and bounded.** Because `retryCount` is not server-enforced, issue exactly one retry for a prompt error or invalid structured result, then preserve the heuristic facts.
6. **Memory schema v2 owns recency and cache.** It includes capped `recent_sessions` plus an optional LLM extraction cache; durable recency is determined from the last three sessions.
